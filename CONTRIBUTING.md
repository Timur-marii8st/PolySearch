# Внесение изменений

Предлагаемый рабочий процесс для команды PolySearch:

1. Описать задачу и проверяемый критерий готовности в issue.
2. Создать отдельную ветку (`docs/...`, `feat/...`, `fix/...`).
3. Внести минимальное целостное изменение, обновить документацию и, после появления кода, тесты.
4. Открыть pull request, указать что проверено и что осталось гипотезой.
5. После ревью объединить с основной веткой.

Примеры сообщений коммитов: `docs: describe ML engine`, `feat: add experiment schema`, `test: verify calibration isolation`.

Не включать ключи доступа, персональные сведения из грантовой заявки, закрытые архивы лабораторий и клиентские данные. Не присваивать стороннему коду лицензию без проверки прав. Сохранять происхождение всех экспериментальных данных и результаты неудачных прогонов. Различать программные тесты, синтетические результаты, архивную оценку и физический пилот.
