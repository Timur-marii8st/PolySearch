# Этап 15 — планирование научных данных

Исследовательский контур, не заменяет production API. Monash и RAFT provisional используются раздельно, исходный QC прежний. Планирование не означает технологический допуск и не генерирует инструкции для оборудования.

## 1. Learning curves и выбор групп

Для каждой из четырёх целей отдельно используются только группы с доступной наблюдаемой меткой данной цели. Это ретроспективное ограничение архива; в будущих измерениях наличие пригодных меток не известно заранее. Группа — комбинация условий Monash или рецепт RAFT; не считать её автоматически одним физическим опытом. Не суммировать бюджеты независимых целевых исследований: несколько свойств могут измеряться одной реакцией, но с разными затратами.

Пять прежних внешних групповых фолдов, пять фиксированных seed, одинаковые первые 3 группы в каждой политике. Кандидаты только из outer train. Дальше строим вложенный порядок групп без повторов. Все политики получают равный бюджет групп. Модель — одна целевая Ridge-голова (alpha=10, фиксирован заранее), clipping молекулярных дескрипторов по train, scaler на train, one-hot контекст, group weights; для масс/Đ log-цель. Это отдельный baseline для измерения learning curve, не замена связанных голов v3. Прогнозы оцениваются на тех же внешних группах. Метрика — среднее абсолютное отклонение внутри каждой группы, затем среднее по всем group/fold/seed оценкам. P90 групповых ошибок — описательная метрика, не доверительный интервал.

Стратегии:
- Random — случайная группа.
- Maximin — максимальная минимальная дистанция в нормированной геометрии кандидатов.
- Ridge variance — максимальный log(1 + xᵀ(AᵀA+I)⁻¹x), fixed-prior D-optimal heuristic.

Это **label-free active experimental design**, а не Bayesian optimization по значению цели или обученная эпистемическая дисперсия. Геометрия известного пула: численные условия без последнего признака времени, RDKit дескрипторы, категориальный контекст. Не используются измеренные временные сетки, метки, признаки QC, число измерений или тестовые группы. Порядок выбирается без просмотра исходов. Бюджеты Monash 3/5/8/12/20/30; RAFT 3/5/10/20/40/80/120/200; применяются только бюджеты, доступные во всех внешних фолдах соответствующей цели.

## 2. Калибровочные размеры

Отдельный эксперимент: на outer train заранее резервируется максимальный возможный пул calibration (4/9/14/19/29/39 групп), оставляя минимум 8 train для Monash и 20 для RAFT. Три фиксированных seed. Одна и та же proper-train модель и те же внешние test-группы для разных размеров calibration; вложенные префиксы, никаких calibration меток при fit. Один максимальный абсолютный остаток на группу для каждой цели, log-space для положительных свойств. Маргинальные 80% и 90% интервалы, без конечного квантили — null. Математические минимумы 4 и 9 групп соответственно (95% — 19). Это необходимое условие конечного ранга, а не доказанный необходимый/достаточный размер эксперимента. Дополнительно ширина и фактическое полногрупповое покрытие, доля строк в условных пределах: конверсия 20 п.п., массы upper/lower ≤3, Đ ≤0,30. Пороги прежние исследовательские, не допуски заказчика.

## 3. Бюджет и план технолога

```bash
python -m polysearch.ml.data_planning --request data/planning/example-budget.json
```

Пример содержит **вымышленные** бюджет, цену и число групп; никакая цена не оценивалась по рынку или лаборатории. Указать валюту, доступный бюджет в minor units, уровень покрытия, по каждой непересекающейся роли train/calibration/validation — существующие пригодные группы, целевой размер и стоимость новой группы. Система считает недостающие группы, требуемые расходы, остаток/дефицит; отклоняет calibration target ниже математического минимума. Не предлагает ослабить качество автоматически и не гарантирует, что заданное число обеспечит нужную точность.

Перед реальным пилотом подтвердить независимую экспериментальную единицу, стоимость полного измерения/контроля качества, ограничения и допустимые кандидаты. Зафиксировать отдельные наборы обучения, калибровки и внешней приёмки. Не выбирать калибровку по её исходам, не переиспользовать тест для настройки. Запланировать остановку/расширение по заранее согласованным критериям. Нужен заказчик и независимые будущие эксперименты.

## 4. Запуск

Выполнить ETL Monash/RAFT из [MOLECULAR_V3](MOLECULAR_V3.md), установить ml,molecular extras. Затем:
```bash
python -m polysearch.ml.learning_benchmark
```

Артефакт report.json содержит все траектории, fold groups, калибровочные префиксы и сводки. Не оценивать реальные затраты или экстраполировать learning curves за границы архива. Результаты не доказывают, что активный выбор уменьшает число физических синтезов.
