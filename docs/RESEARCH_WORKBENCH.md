# Этап 16 — исследовательская лаборатория PolySearch

## Назначение и границы

Рабочий интерфейс `/research` объединяет пользовательские групповые данные, реестр реализаций моделей, выбор по CV, калибровку, контрольную проверку, прогнозы и бюджетный план следующих измерений. Серверный API пилотных кампаний и прежний GP-оптимизатор не менялись. Научные результаты Monash/RAFT, кинетические модели и BoTorch сохраняются отдельными воспроизводимыми benchmark/CLI; эта версия не запускает все исследовательские алгоритмы автоматически и не загружает архивы в БД заказчика. Встроенный пример — только явно маркированная программная фикстура. Не является автономным управлением синтезом или доказательством безопасности.

## Схема данных

CSV UTF-8, точные заголовки: group_id,role, затем имена факторов, имена целей и smiles **только при molecular=true**. Порядок колонок произвольный, имена уникальны. Роль train / calibration / validation назначает оператор до подбора модели. Один group_id не может пересекать роли, а одинаковая точка факторов + canonical SMILES не может быть разнесена по разным группам. Коррелированные измерения, повторные рецепты и временные кривые необходимо группировать по их реальной независимой единице; программа не способна доказать независимость физических опытов. Не вводить прогнозы как наблюдения. Пропуски целей остаются пустыми, не превращаются в нули. Не менее 6 train и 2 validation групп с измерениями каждой цели; в каждом внутреннем train-fold не менее 2 групп на цель. Калибровка может отсутствовать, но тогда прогнозы кандидатов не выдаются. Точки должны проходить численные bounds и линейные constraints ProjectConfig. Эти проверки не являются технологическим допуском.

Пример структуры (без физического значения):
```csv
group_id,role,x,property
g1,train,0.1,0.26
g2,train,0.3,0.38
g3,calibration,0.4,0.44
g4,validation,0.5,0.50
```
Это только заголовок и фрагмент; для расчёта требуются минимальные группы. В интерфейсе кнопка «Загрузить тестовый пример» заполняет полный валидный fixture.

## Реестр и выбор моделей

| ID | Реализация | Доступность |
|---|---|---|
| mean | Среднее с равным весом групп | базовая |
| ridge | Независимые Ridge, alpha=.1 | базовая |
| gp | Независимые Matérn 5/2 GP, фиксированные prior/noise, не более 180 train-строк на цель | базовая |
| rdkit_ridge | Ridge + 12 RDKit дескрипторов, clipping по observed-target train | molecular extra |
| coupled | Связанные логарифмические головы масс v3, численные признаки, alpha=10 | coupled_mass |
| rdkit_coupled | BoundedMolecularModel из этапа 14, alpha=10 | molecular + coupled_mass |

Все адаптеры используют fit/predict. Масштаб факторов — заданные границы (не метки), вес строки обратно пропорционален числу наблюдений группы для конкретной цели. В режиме auto сравниваются только совместимые реализации в 3-fold GroupKFold на train; средняя по целям group macro MAE, делённая на заранее объявленный target.scale. Фиксированные гиперпараметры; никакой настройки по calibration/validation. Явный выбор модели также проверяется CV, но не сравнивается с остальными. Это небольшой исследовательский baseline selector, не AutoML с гарантией обобщения. При coupled_mass=true разрешены только связанные модели; строго четыре цели в порядке conversion_fraction (fraction), mn_g_mol (g/mol), mw_g_mol (g/mol), dispersity (1). Наблюдения физически проверяются, выходы обеспечивают Mn>0, Mw=Mn×Đ и Đ≥1, конверсия 0–1. Неполные метки поддерживаются, массы не вычисляются из пропущенных измерений для обучения. В generic режиме алгебраические свойства не гарантируются.

RDKit optional, базовый Docker не включает его. Чтобы использовать SMILES, локально установить `pip install -e ".[molecular]"`. Дополнительные научные зависимости ещё требуют отдельного security review. Неизвестные молекулы не получают прогноз даже при близости структуры; автоматически не подменять их известными.

## Интервалы и визуализация

Proper train используется для выбора/fit; отдельные calibration группы для максимального абсолютного остатка по каждой измеряемой цели и группе в исходных единицах. 80/90/95% marginal split conformal, конечный квантиль требует минимум 4/9/19 групп соответственно. Даже при его наличии нужна пользовательская допустимая ширина. Проверка домена — точная известная молекула (при RDKit), минимум 3 train группы с этой меткой, координаты в наблюдаемых target/molecule min/max и RMS расстояние ≤.35 в нормированных факторных единицах. Для coupled интервал пересекается с физической областью, проверка ширины консервативно до clipping. Причины отказа: unseen_molecule, insufficient_target_groups, outside_observed_range, sparse_process_support, interval_unavailable, interval_too_wide. При отказе prediction/interval null. Маргинальные интервалы не являются совместным множеством или гарантией покрытия после отбора. Пороги инженерные; заказчик должен согласовать ширину и проверить физический смысл.

Validation отображает group macro MAE, эмпирическое полногрупповое покрытие, число поддержанных измерений, диагностический scatter факта и прогноза (до 200 меток на свойство). Отказанные diagnostic predictions предназначены только для оценки ошибки, не для предложений опытов. Повторное использование validation для изменения модели/конфигурации лишает его независимости; новые проверки должны использовать новые группы.

## План новых измерений

Не генерирует химические режимы. Оператор передаёт предварительно проверенный пул кандидатов: id, parameters, cost_minor, при molecular — smiles. Требуется явное подтверждение происхождения пула (самодекларация, не ЭП и не approval технолога в API пилота). Дубли измеренных точек и ID запрещены. Greedy maximin_per_cost: максимальная минимальная дистанция к train и ранее выбранным кандидатам на единицу заданной стоимости; при молекулярном режиме добавляется расстояние между категориями идентичности. Все предложения только из пула и в пределах бюджета/лимита. Не использует measured labels или цели и не оптимизирует ожидаемое химическое свойство. Допускает предложения измерений при abstain — это запрос данных, не прогноз успеха. Перед физической попыткой пройти обычное согласование пилота.

Для раздельного планирования количества train/calibration/validation и их затрат сохраняется [бюджетный CLI](DATA_PLANNING.md).

## API и версия

GET /api/research/catalog; GET /api/research/runs?limit=20&offset=0; POST /api/research/runs; GET /api/research/runs/{id}. Схема POST в Swagger. Полный JSON содержит исходный CSV, конфигурацию, значения ширин, пул, результаты и происхождение; хранить в закрытом контуре. actor определяется серверной сессией. Admin/researcher создают, все четыре роли читают общий реестр одной организации; не изолирует данные проектов или разных клиентов. Изменение/удаление существующего расчёта через API не предусмотрено. Хеш input_sha256 всего снимка, training_sha256 нормализованного train и конфигурации, runtime_sha256 версий библиотек и хешей исходников, model_version = хеш runtime + train + selected_model, record_sha256 полной записи. Проверяется целостность при чтении. Это версии воспроизводимого рецепта обучения, **не сериализованные веса, подписи или защищённый от администратора аудит**. Автоматическое повторное исполнение старого окружения и promotion отсутствуют.

SQLite/PostgreSQL, независимая таблица research_runs. Сброс обычного workspace её не удаляет. Миграция из SQLite включает снимки, backup содержит их, restore проверяет таблицу. До 100 расчётов, 600 CSV-строк, 100 кандидатов, 20 предложений, 200000 символов CSV и общий body limit 256 КиБ. Один исследовательский fit на процесс, без DB-lock на время расчёта. Не рассчитано на многопроцессную очередь, MLflow/полноценное хранение артефактов, большие наборы или производственную нагрузку. Нет автоматической отправки исходных данных в сеть. Развёртывать только по существующей инструкции, перед внешним запуском провести приёмку ИТ/ИБ.

## Демонстрация

Запустить локальное приложение (см. WEB_UI или DEPLOYMENT), открыть /research, загрузить тестовый пример, нажать «Обучить и проверить модели». Показать выбор модели, раздельные группы, график, отказ за пределами train и предложения по условной цене. Экспортировать JSON; обновить страницу и показать неизменяемый расчёт. Не выдавать значения фикстуры за реальные, не заявлять экономию опытов. Для заказчика отдельно согласовать формат CSV, независимую единицу, бюджет и внешние данные.
