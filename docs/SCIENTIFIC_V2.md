# Научное ядро v2 — экспериментальная ветка

Не заменяет универсальный API / GP пилота. Сравнение на том же provisional Monash MMA v1, 785 строк, 15 групп. Это повторное исследование известного архива, не независимый тест.

## Модели
- Ridge, CatBoost, обычный GP, кинетический baseline — прежние алгоритмы и сетки.
- Rate Ridge: на каждой группе условий независимо оценить log(k) минимизацией MSE кривой X=1-exp(-kt). Одна оценка на группу. Регрессия Ridge на обратной абсолютной температуре и log(1+CT/CM/0.05).
- Rate GP: тот же физический тренд + Matérn 5/2 GP на остатках log-rate. Фиксированные prior scales выбираются только внутренней групповой CV; отдельный scaler на train. Предсказание медианы конверсии, монотонно по времени, ноль в t=0, диапазон [0,1]. Это эмпирическое эффективное приближение, не механистическая кинетика. Не моделирует индукцию, нелинейную кинетику, скачки или Mn/Đ.
- Kinetic Residual GP: кинетический baseline + GP на остатках конверсии, масштабирование поправки t/(1+t), shrinkage и clipping. Может нарушать монотонность, работает с коррелированными строками.

## Проверка
Пять прежних внешних фолдов, внутренние 3 group folds для выбора гиперпараметров по macro MAE. Нормализация и оценка log-rate только внутри train. В отдельном анализе исключены MMA-13 и MMA-16. Проверяем ошибку, RMSE/R², число убывающих шагов на сетке каждой отложенной кривой и ненулевой прогноз в t=0. Shape tests — инварианты принятой математической модели, не доказательство корректной химии.

Rate GP: номинальные 90% интервалы латентной скорости (без измерительного шума и неопределённости тренда); residual GP — условные интервалы с assumed residual noise. Для каждого гибрида отдельно group split conformal 80%: 4 calibration-группы, подбор гиперпараметров повторно только на proper train. Максимальный нормированный остаток на группу. С 4 группами конечный 90% квантиль недоступен. Обменность не установлена, покрытие оценивается эмпирически.

## Последовательный выбор и стоимость

Расширен прежний конечный MMA-пул: rate_ridge_greedy и rate_gp_ei, те же 64 seed, 3 стартовые реакции и 10 запросов. Используются только раскрытые медианы измерений в окне 6 ± 0,25 мин, а не целые скрытые кривые. Для модели эффективной скорости время аппроксимируется 6 мин. Параметры фиксированы заранее (alpha=1, length=1, signal=.5, noise=.25 в log-rate). EI — по 128 латентным семплам; наблюдаемый incumbent. Прежние пять политик пересчитываются без изменения протокола.

BoTorch 0.18.1 и GPyTorch — отдельный optional research extra, CPU torch 2.10.0 в отдельном CI; зависимости не входят в базовый сервер. qLogNEI и qLogNEHVI по [документации BoTorch](https://botorch.readthedocs.io/en/latest/acquisition.html), q=1, SingleTaskGP, фиксированное допущение о шуме, QMC. На известном конечном пуле выбираются только неиспользованные и доступные по бюджету точки. Все цели максимизируются; минимизируемое свойство необходимо заранее преобразовать (например, минус значение). Две цели требуют заранее согласованной reference point. При известных положительных затратах режим per_cost использует log-acquisition − log(cost); это эвристика gain/cost, не глобальная оптимизация многопериодного бюджета.

- Реальный MMA: отдельно 8 paired seed, бюджет 8 реакций (3 стартовые), qLogNEI vs random/Ridge/GP-EI. Равная условная стоимость запроса, наблюдается только конверсия. Не сравнивать числа напрямую со сводками 64 seed.
- Синтетическая двумерная задача: 25 дискретных вариантов, две конфликтующие цели и известные безразмерные стоимости 1–5, бюджет 16; 4 paired seed, общие 3 стартовые точки, random vs qLogNEHVI vs qLogNEHVI/cost. Сравнение наблюдаемой hypervolume и расходов. **Не реальные затраты, не химические свойства.**
- BoTorch используется только в исследовательском CLI; отсутствие отдельного доказательства переносимости и security review исключает его автоматическое включение в beta API.

```bash
python -m polysearch.bo.hybrid_replay
# В отдельном исследовательском окружении:
python -m pip install torch==2.10.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e ".[ml,research]"
python -m polysearch.bo.botorch_benchmark
```

Дальше: новый источник данных и независимые физические группы; полноценные многокритериальные измерения и фактические стоимости заказчика. Monash BA/VA — кандидаты для внешней проверки по мономерам после отдельного QC и сопоставления единиц; до этого никакого утверждения о переносимости.
