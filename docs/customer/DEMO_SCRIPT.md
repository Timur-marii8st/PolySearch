# Демонстрация PolySearch (10–15 минут)

Цель: показать рабочую цепочку, а не заявить промышленную эффективность.

1. Обзор: объяснить научную постановку и текущие результаты [Monash](../MONASH_ML_RESULTS.md), отдельно сказать о QC и отсутствии физического пилота.
2. Открыть обычное рабочее пространство, запустить синтетическое демо, показать график истории, цели, рекомендацию и интервалы.
3. Сохранить синтетический результат, обновить модель. Пояснить, что значения искусственные.
4. Для файлового обмена использовать отдельный fixture-контур: выполнить `POLYSEARCH_AUTH=local python -m polysearch.lab_demo --out artifacts/lab-demo`. Показать work order, результат, provenance, решение и отчёт. Не смешивать демонстрационные и фактические данные.
5. В серверном стенде показать роли исследователя и технолога, согласование и журнал обмена. Для живого сценария использовать отдельную одноразовую базу без данных заказчика, заранее маркированную SOFTWARE FIXTURE, не рабочий контур.
6. Перейти к вопросам discovery: существующий baseline, стоимость опытов, независимые измерения, доступность LIMS, сроки и решение о пилоте.

Материалы: [предложение пилота](PILOT_OFFER.md), [анкета](DISCOVERY.md), [приёмка](ACCEPTANCE.md). Не демонстрировать чужие данные, не обещать конкретный эффект, не отправлять экспериментальные задания на физическое оборудование.

## Исследовательская лаборатория

Открыть `/research`, загрузить явную программную фикстуру, показать train-only CV, калибровку, validation scatter, отказы и бюджетный план из предоставленного пула. Экспортировать неизменяемый расчёт. Не смешивать со штатным GP пилота и не выдавать результаты фикстуры за полимерные измерения. [Протокол](../RESEARCH_WORKBENCH.md).
